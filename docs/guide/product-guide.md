# DeepSeek Harness（dsh）产品说明书

> 本说明书面向**没有编程经验**的用户，用通俗的语言介绍 DeepSeek Harness 是什么、怎么用、能做什么。遇到专业词汇时，会紧跟括号用大白话解释。

---

## 第 1 章：这个项目是做什么的

当你需要**自己搭一个 AI 助手来帮你写代码、改文件、跑命令、查资料**的时候，DeepSeek Harness（简称 `dsh`）就是为你准备的。它像一个"AI 助手工厂"：装好之后，你就能拥有一个类似 ChatGPT 的对话式助手，但它是专门为"动手干活"设计的——不只是陪你聊天，而是真的会去读写你的文件、执行你电脑上的命令、搜索网页，然后把结果拿回来给你看。DeepSeek 自己的网页版 AI 助手（http://127.0.0.1:3080）就是由它驱动的，你可以把它理解成"DeepSeek 官方 AI 助手的开源底座"。

它最特别的地方是**"一切皆插件"**：写代码、读文件、跑命令、搜网页……这些能力不是焊死的，而是像乐高积木一样可以自由拼装。你觉得某个能力不好用，可以换掉它；你觉得缺什么能力，可以自己加一块"积木"。这种设计让它非常灵活，既可以开箱即用，也能被深度改造。

这个项目由 DeepSeek AI 公司开发并开源（免费公开源代码），使用 MIT 许可证——意味着任何人都可以免费使用、修改，甚至拿去做商业产品。目前它处于"开发者预览"阶段，也就是说还在快速打磨中，未来可能会有比较大的变化，但核心功能和架构已经成型，足够你上手体验了。

## 第 2 章：开始之前你需要准备什么

在第一次运行之前，你需要准备三样东西。按顺序准备好，总共大约需要 **15~25 分钟**。

### 1. 安装 Node.js（必需，约 5~10 分钟）

- **这是什么**：一个让 JavaScript 程序（包括 dsh 本身）能跑起来的"运行环境"，可以理解成电脑里的一个"程序播放器"。
- **怎么做**：去 Node.js 官网（https://nodejs.org）下载安装包，一路点"下一步"装完即可。
- **版本要求**：需要 **22.19 或更高、24 或更高** 的版本（通俗说就是"装新版"）。安装完成后，可以打开"命令提示符"（Windows）或"终端"（Mac），输入 `node --version`，能看到版本号就说明装好了。

### 2. 安装 pnpm（推荐，约 2~3 分钟）

- **这是什么**：一个帮你"下载和管理软件零件"的小工具，属于可选但强烈推荐——如果你用源码方式运行，就一定要装它。
- **怎么做**：在终端里输入 `npm install -g pnpm`，回车等待完成即可。

### 3. 准备 DeepSeek API Key（必需，约 5~10 分钟）

- **这是什么**：一串"钥匙"，用来证明你有权限调用 DeepSeek 的 AI 模型。dsh 本身不包含 AI 大脑，它的大脑是通过这串钥匙向 DeepSeek 的云服务"借"来的。
- **怎么做**：到 DeepSeek 开放平台（https://platform.deepseek.com）注册账号，创建 API Key（一串字母数字），然后把它填进电脑的"环境变量"里，变量名叫 `DEEPSEEK_API_KEY`（通俗理解：在电脑里存一条名为 `DEEPSEEK_API_KEY` 的记录，值就是你的钥匙）。具体填法网上搜"Windows 设置环境变量"或"Mac 设置环境变量"就有图文教程。
- **注意**：调用 AI 模型会消耗账户额度（按使用量计费，价格很低），没有这串钥匙的话，dsh 也能启动，但 AI 不会真正工作（项目里很多测试会自动跳过）。

### 4. 其他说明

- **操作系统**：Windows、macOS、Linux 都可以。
- **网络**：需要能访问 npm（下载软件）和 DeepSeek 服务（调用模型）。

## 第 3 章：快速开始

最快的方式是**一条命令跑起来**，全程约 5~10 分钟（前提是第 2 章的准备工作已完成）。

### 方式一：用 npm 一条命令启动（推荐新手）

1. 打开终端（Windows 的命令提示符 / PowerShell，或 Mac 的终端）。
2. 输入下面这条命令并回车：

```sh
npx @deepseek-ai/dsh web
```

3. 第一次运行会自动下载所需文件（约 1~3 分钟，视网速而定），之后会看到类似下面的输出：

```
DeepSeek Harness is running
Web UI available at: http://127.0.0.1:3080
```

4. 打开浏览器，访问 **http://127.0.0.1:3080**，你就看到了 dsh 的网页界面。

### 方式二：从源码运行（适合想折腾、想二次开发的人）

```sh
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install      # 安装依赖，约 3~10 分钟
pnpm run build    # 编译项目，约 1~5 分钟
pnpm dsh web      # 启动，同样访问 http://127.0.0.1:3080
```

### 启动后你会看到什么

一个聊天界面（类似 ChatGPT 的对话框）。第一次使用，按以下两步配置：

1. 打开 **设置 → 模型**，填入你的 DeepSeek API Key 并保存（配置立即生效，不用重启）。
2. 点击 **选择工作区**，把你存放项目的文件夹加进来并选中（工作区 = 允许 AI 动手操作的那个文件夹）。

然后就可以在输入框里打字了。试试输入：

> 介绍一下这个文件夹里都有什么

AI 会读取文件、给你一份总结——恭喜，你的第一个 AI 编程助手跑起来了！

## 第 4 章：详细使用步骤

dsh 一共有**三种使用方式**，按需选择，可以混用。

### 方式一：Web 网页界面（推荐日常使用）— 必需的基础操作

这是最直观的方式，适合绝大多数人。

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 启动服务器 | 终端运行 `npx @deepseek-ai/dsh web`（保持终端开着别关） |
| 2 | 打开网页 | 浏览器访问 http://127.0.0.1:3080 |
| 3 | 配置模型（必需） | 设置 → 模型 → 填入 DeepSeek API Key 并保存 |
| 4 | 选择工作区（必需） | 添加并选中一个文件夹作为 AI 的"工作地盘" |
| 5 | 开始对话（必需） | 在输入框描述你想做的事，回车发送 |
| 6 | 处理审批请求（可选） | 当 AI 想做一些敏感操作（比如修改系统文件）时，网页会弹窗问你"允许吗"，你点同意或拒绝 |
| 7 | 查看历史会话（可选） | 对话记录会被自动保存，下次打开还能接着聊 |

> **注意**：网页界面只在本机生效（地址是 127.0.0.1 开头的本地地址），别人访问不到，这是安全设计。

### 方式二：命令行一次性任务（headless，适合跑自动化）— 可选

不想开网页，只想让 AI 干一件具体的事然后退出，用这个方式。它叫 headless（"无头"），意思是"没有界面的操作"。

```sh
dsh --profile headless "帮我检查一下这个项目里有没有语法错误"
```

- **必需**：提前设置好 `DEEPSEEK_API_KEY` 环境变量。
- **预期结果**：终端里直接打印出 AI 的答复，任务结束进程退出。
- **适合**：写脚本定时调用、服务器上跑批处理任务等不需要人盯着的场景。

### 方式三：ACP 自动化服务器（给其他程序调用）— 可选

ACP（Agent Client Protocol，智能体客户端协议）是一个让"程序之间对话"的标准接口。启动后，dsh 会变成一个"AI 服务后台"，其他软件可以通过这个接口调用它。

```sh
dsh acp
```

- **必需**：设置好 `DEEPSEEK_API_KEY` 环境变量。
- **预期结果**：终端显示服务已就绪，等待其他程序连接。
- **适合**：你想把 AI 能力嵌入自己的软件、机器人或自动化流程里的时候。
- **注意**：这是给"程序"用的接口，普通用户日常用不到，属于进阶功能。

> **小结**：日常聊天、改代码用**方式一**；自动化批量任务用**方式二**；给程序当"后台大脑"用**方式三**。

## 第 5 章：项目有哪些模块

dsh 由很多小模块拼成，下面是普通用户最需要了解的 8 个核心模块。

### 模块 1：系统提示词（AI 的"人设和规则"）
- **一句话说明**：给 AI 设定"你是谁、说话什么风格、做事什么规矩"的一段开场白。
- **包含的功能**：
  - 预设人设：默认给 AI 一套"专业、谨慎、先验证再回答"的编程助手性格。
  - 自定义人设：你可以通过配置（见第 6 章 `persona`）改成任何风格，比如"用小学生都能听懂的话解释代码"。
- **和其他模块的关系**：它是每次对话的"第一句话"，AI 的所有行为都受它约束。

### 模块 2：工具集（AI 的"手和脚"）
- **一句话说明**：让 AI 能真正动手做事的能力清单，包括执行命令、读写文件、搜索网页等。
- **包含的功能**：
  - 执行命令（bash）：AI 可以在你的电脑上运行命令，比如"运行测试"。
  - 读写文件：AI 能查看、新建、修改工作区里的文件。
  - 搜索网页：AI 能上网查资料来回答你的问题。
- **和其他模块的关系**：工具是 AI 的"输出器官"；沙箱模块（模块 8）决定这些工具能用多大力气。

### 模块 3：会话持久化（AI 的"记忆"）
- **一句话说明**：把对话历史存到硬盘上，关掉程序再打开，聊天记录还在。
- **包含的功能**：
  - 自动保存：每一轮对话都会被记录。
  - 断点续聊：重启后可以继续之前的会话，AI 还记得之前说过什么。
- **和其他模块的关系**：它为压缩模块（模块 7）提供"历史素材"，压缩后的摘要也存回这里。

### 模块 4：子智能体（AI 的"分身"）
- **一句话说明**：让主 AI 把子任务派给"分身"去干，自己专心统筹。
- **包含的功能**：
  - 派活：任务复杂时，AI 可以开几个分身并行处理不同部分。
  - 回收结果：分身干完活把结果交回主 AI 汇总。
- **和其他模块的关系**：分身也使用同样的工具集和沙箱规则，不会"越权"。

### 模块 5：工作流（多步骤任务"流水线"）
- **一句话说明**：把"先做 A、再做 B、最后做 C"的多步任务编排成一条流水线自动跑。
- **包含的功能**：
  - 步骤编排：定义任务的先后顺序和依赖关系。
  - 自动执行：一次启动，按剧本一步步走完。
- **和其他模块的关系**：流水线里每一步都可以调用工具集，也可以派给子智能体。

### 模块 6：技能（可复用的"指令包"）
- **一句话说明**：把一段"怎么做某类事"的完整经验打包，以后随时调用。
- **包含的功能**：
  - 打包复用：比如"写周报"技能，包含写周报的全部步骤和格式要求，一次配置多次使用。
  - 按需加载：只有用到时才把对应指令加载给 AI，节省空间。
- **和其他模块的关系**：技能本质上是"系统提示词"的高级形态，按场景动态装配。

### 模块 7：压缩（对话太长时的"自动总结"）
- **一句话说明**：对话太长、快超出 AI 的记忆上限时，自动把早期内容总结成摘要，腾出空间。
- **包含的功能**：
  - 阈值触发：对话量达到 80% 上限时自动启动。
  - 智能总结：把旧对话浓缩成要点，保留关键信息（详见第 9 章的"KV 缓存对齐"亮点）。
- **和其他模块的关系**：读取会话持久化模块的旧记录，压缩后继续写入记忆。

### 模块 8：沙箱（AI 的"活动范围围栏"）
- **一句话说明**：限制 AI 能碰哪些文件、有多大权限，防止它搞破坏。
- **包含的功能**：
  - 三档权限：只读（只能看不能改）、工作区可写（只能在指定文件夹里改）、完全放行（不设限，危险）。
  - 审批拦截：遇到权限边界时先问你"要不要允许"。
- **和其他模块的关系**：它罩着工具集——AI 的每只手伸出去之前，都要先过沙箱这关。

### 模块关系总览（用大白话描述）

> 你（用户）向 **AI 主脑**（由系统提示词设定人设）下指令；主脑通过**工具集**动手做事，工具被**沙箱**管着；做事过程中**子智能体**帮忙打下手、**工作流**负责排顺序；聊天的每句话都存入**会话持久化**的记忆库，太长时由**压缩**模块帮忙"翻旧账总结"；而**技能**模块随时给主脑递上"经验手册"。所有模块像插头一样插在同一个底座上，这就是"一切皆插件"。

## 第 6 章：可以自定义的配置

dsh 的核心配置文件叫 **cordis.yml**（在项目目录里，用记事本就能编辑）。大部分个性化设置都在这里改。

| 配置项 | 在哪里改 | 默认值 | 改成什么会怎样 | 建议 |
|--------|---------|--------|---------------|------|
| `persona`（AI 人设） | cordis.yml | 官方预设编程助手人设 | 改成"你是我的中文写作教练"等，AI 会按新风格回答 | 按需定制，人设写得越具体，AI 越听话 |
| `model`（模型选择） | cordis.yml 或网页"设置→模型" | `deepseek-v4-flash`（快） | 换成 `deepseek-v4-pro`（强）：回答质量更高但更慢、更贵 | 日常用 flash，复杂任务临时换 pro |
| `sandbox`（文件权限档位） | cordis.yml | `read-only`（只读） | `workspace-write`（工作区内可写）、`danger-full-access`（完全放行） | 保持前两档，**不要轻易用完全放行** |
| `thinking`（深度思考开关） | cordis.yml | `enabled`（开启） | 关闭后 AI 不"先想后答"，响应更快但容易答错 | 简单问题可关，复杂问题开着 |
| `reasoningEffort`（思考投入度） | cordis.yml | `max`（最大） | 调成 `high`/`off`，AI 想得少一些、回得快一些 | 想省钱省时再调低 |
| `DEEPSEEK_API_KEY`（API 钥匙） | 系统环境变量 | 无 | 不设置则 AI 不工作 | 必填，启动前设置好 |
| 端口（网页访问地址） | cordis.yml 的 webserver 段 | 3080 | 改成别的数字，访问地址跟着变 | 端口被占用时才需要改 |

> **推荐做法**：新手只改 `persona` 和模型两项就够了；沙箱档位、思考深度这些，等熟悉了再动。`danger-full-access` 属于"拆掉安全围栏"，强烈不建议。

## 第 7 章：输入输出示例

下面的示例按从简单到复杂的顺序排列。示例输出为**示意**，实际内容取决于你的任务和模型。

### 示例 1：让 AI 改代码（最简单）

**我想做什么**：让 AI 把一个脚本里的日期格式从"2024/01/05"改成"2024-01-05"。

**我输入了什么**（在 Web 网页输入框里）：
```
帮我把 report.js 里所有 "2024/01/05" 这种斜杠日期，改成 "2024-01-05" 这种横杠格式。
```

**项目返回了什么**（示意）：
```
已修改 report.js：
- 第 12 行：2024/01/05 → 2024-01-05
- 第 34 行：2024/01/06 → 2024-01-06
- 第 78 行：2024/01/08 → 2024-01-08
共修改 3 处。已检查没有其他斜杠日期遗漏。
```

**这个结果是什么意思**：AI 读懂了文件，找到了所有需要改的地方，改完还复查了一遍。你可以打开文件确认改动是否正确。

### 示例 2：让 AI 跑命令

**我想做什么**：让 AI 运行项目的测试并汇报结果。

**我输入了什么**：
```
运行这个项目的测试，然后把结果总结给我。
```

**项目返回了什么**（示意）：
```
我运行了 `npm test`，输出如下：
✓ 42 个测试通过
✗ 1 个测试失败：test/tools.test.js 第 87 行
失败原因：期望返回 3，实际返回 4。
我查看了相关代码，可能是 getCount 函数里的边界条件写错了，要我修一下吗？
```

**这个结果是什么意思**：AI 不只执行了命令，还分析了失败原因并给出了下一步建议——这是它比普通"脚本"强的地方。

### 示例 3：让 AI 搜索资料

**我想做什么**：让 AI 上网查最新的信息。

**我输入了什么**：
```
搜索一下 Node.js 目前最新的 LTS（长期支持）版本是哪个，什么时候发布的支持到什么时候。
```

**项目返回了什么**（示意）：
```
根据搜索结果：Node.js 当前最新的 LTS 版本是 v24.x（发布于 2025 年 10 月，支持到 2028 年 4 月）。
来源：nodejs.org 官方发布页。
注：搜索结果来自网络，建议以官方页面为准。
```

**这个结果是什么意思**：AI 真的上网查了资料并给出答案和来源。注意它会提醒你"以官方为准"——因为网页信息可能滞后，这是 AI 负责任的表现。

## 第 8 章：什么情况适合用 / 不适合用

**适合用的场景：**
- **场景 1：个人开发者想有个"随叫随到的编程搭档"**——帮你写代码、改 bug、跑测试、解释陌生代码，省去反复搜索和切换工具的时间。
- **场景 2：自动化重复性工作**——比如每天定时让 AI 检查代码质量、生成日报、批量整理文件，用命令行方式挂到脚本里。
- **场景 3：喜欢折腾、想自建 AI 助手的人**——想拥有自己的、可定制、数据在自己手里的 AI 助手，而不是只能用别人家的现成产品。
- **场景 4：想把 AI 能力嵌进自己的软件**——通过 ACP 接口，把你的应用变成"能动手干活"的智能应用。

**不适合用的场景：**
- **场景 1：完全不想碰命令行的人**——安装和启动必须用命令行操作（虽然日常使用有网页界面，但"启动"这一步绕不开）。替代方案：直接用 DeepSeek 官方网页版或 ChatGPT 等现成产品。
- **场景 2：需要稳定"交钥匙"服务的人**——项目处于开发者预览期，升级可能带来不兼容变化（见第 9 章），生产环境用要谨慎。替代方案：等正式版，或用成熟商业产品。
- **场景 3：任务涉及极高敏感数据**——虽然沙箱能限制文件权限，但调用云端模型意味着数据会发送给 DeepSeek 服务。涉密场景建议先确认数据合规要求。
- **场景 4：只需要纯聊天、不干活**——dsh 是"动手型"助手，纯闲聊体验不如专门的聊天产品，杀鸡不用牛刀。

## 第 9 章：优点与不足

> 本章基于对项目代码的实际观察。

**优点：**
- **插件化设计，极其灵活**：每个能力都是一块可拆装的"积木"，想换想加都容易。这是它区别于多数同类产品的最大特色——不满足于"能用"，而是"想怎么改都行"。
- **多智能体协作**：能派"分身"并行干活再汇总，复杂任务处理起来有条理、速度快。
- **对话压缩技术讲究（KV 缓存对齐）**：对话太长时自动总结旧内容，而且压缩方式会"对齐" AI 的内部缓存（KV 缓存，见第 11 章），尽量让压缩后的回答速度不受影响。这个细节很多同类产品做不到。
- **安全设计到位**：三档文件权限沙箱 + 关键操作人工审批，让"放手让 AI 干活"这件事变得相对安心。
- **三种使用方式齐全**：网页界面、命令行、程序接口，从新手到开发者都能找到入口。

**不足：**
- **开发者预览期，变化快**：项目明说"未来会有破坏兼容性的变更"，今天能用的功能明天可能改名字或变用法，升级需谨慎。应对办法：留意官方公告，重要环境固定版本。
- **有学习门槛**：安装启动要会敲命令行、配置要会改配置文件，对纯小白不友好。应对办法：照着本说明书做，日常使用集中在网页界面即可。
- **文档偏技术化**：很多说明文档面向开发者撰写，非技术用户查阅时有障碍。应对办法：以本说明书和网页界面内提示为主。

## 第 10 章：常见问题与排错

**Q1：安装时提示 Node.js 版本太低 / 安装失败**
- 可能原因：Node.js 版本低于 22.19，或下载网络不稳定。
- 解决办法：去 nodejs.org 下载最新 LTS 版本重装，装完运行 `node --version` 确认版本号 ≥ 22.19；网络问题可稍后重试，或配置 npm 国内镜像（搜索"npm 镜像设置"有教程）。

**Q2：输入 `npx @deepseek-ai/dsh web` 提示找不到命令 / 报错**
- 可能原因：npx 没装好（Node.js 安装不完整），或首次下载超时。
- 解决办法：重装 Node.js；或先运行 `npm install -g @deepseek-ai/dsh` 全局安装，再直接运行 `dsh web`。

**Q3：网页能打开，但发消息 AI 不回复 / 报"API Key 无效"**
- 可能原因：API Key 没填、填错了、或者环境变量名不对。
- 解决办法：到 DeepSeek 开放平台重新复制 Key，在网页"设置→模型"里粘贴保存；如果用命令行方式，检查环境变量 `DEEPSEEK_API_KEY` 是否设置正确（重新打开终端让环境变量生效）。
- 注意：API Key 形如一长串字母数字，复制时别带空格。

**Q4：AI 说"没有权限" / 写入文件失败**
- 可能原因：沙箱处于"只读"档位，AI 只能看不能改。
- 解决办法：这是**安全设计**，不是故障。想让 AI 改文件，把沙箱档位调到"工作区可写"，并确保要改的文件在选定的工作区文件夹内；或遇到审批弹窗时点"允许"。

**Q5：AI 的回答不符合预期**
- 可能原因：任务描述太模糊、模型选择不合适（默认 flash 偏快但能力弱于 pro）、人设约束不够。
- 解决办法：把需求写具体（"做什么、改哪个文件、做成什么样"）；复杂任务临时切换到 `deepseek-v4-pro` 模型；在 `persona` 里补充规则（如"改代码前先解释你的方案"）。

**Q6：端口被占用，网页打不开**
- 可能原因：3080 端口被其他程序占用。
- 解决办法：在 cordis.yml 的 webserver 配置里把端口改成 3081 等未占用数字，然后访问对应地址。

**Q7：运行测试报错，无法启动**
- 可能原因：依赖没装全或编译失败（源码方式运行时常见）。
- 解决办法：回到项目目录依次执行 `pnpm install` → `pnpm run build`，看到成功提示后再 `pnpm dsh web`。

## 第 11 章：术语表

| 术语 | 通俗解释 |
|------|---------|
| Agent（智能体） | 一个能"理解指令并动手做事"的 AI 程序，不只是回答问题，还会调用工具完成任务 |
| Harness | 直译"挽具/控制装置"，这里指"驱动和管理智能体的一套框架"，dsh 就是这样一个框架 |
| 插件（Plugin） | 一块可以插拔的功能"积木"，如"读文件""跑命令"各是一块，想用就插上，不想用就拔掉 |
| 沙箱（Sandbox） | 给 AI 画的"活动范围围栏"，限制它能读写哪些文件、有多大权限 |
| Token | AI 处理文字的最小单位，大约 1 个汉字 ≈ 1~2 个 token；对话越长消耗的 token 越多，费用也越高 |
| 系统提示词（System Prompt） | 每次对话前发给 AI 的"开场白"，设定它的身份、风格和规则 |
| 多智能体（Multi-agent） | 多个 AI 协作干活：一个主智能体统筹，派"分身"并行处理子任务 |
| API Key | 一串类似密码的字符，用来证明"你是你"并调用 AI 服务，需要保密 |
| API | 程序之间互相"对话"的约定接口，可以理解为"传话窗口" |
| 环境变量 | 存在操作系统里的"全局小纸条"，程序运行时可以读取，`DEEPSEEK_API_KEY` 就是其中一张 |
| 命令行 / 终端 | 一个靠打字输入指令操作电脑的黑窗口，比鼠标操作更底层、更强大 |
| CLI | 命令行工具的缩写，指"靠打字运行的软件" |
| Web GUI | 网页图形界面，指在浏览器里用鼠标操作的界面，如 http://127.0.0.1:3080 |
| ACP | Agent Client Protocol 的缩写，一种让"程序之间调用 AI"的标准接口 |
| 工作流（Workflow） | 把多步任务按顺序编排好、一次自动跑完的"流水线" |
| 技能（Skill） | 打包好的一整套"做事经验"，告诉 AI"这类事情按这个套路做" |
| 会话（Session） | 一次连续的对话，从开始聊天到结束/关闭算一个会话 |
| 会话持久化 | 把对话记录存到硬盘上，重启后还能找回历史 |
| 压缩（Compaction） | 对话太长时自动把旧内容总结成摘要，腾出记忆空间 |
| KV 缓存 | AI 推理时的"草稿纸"：模型把算过的中间结果记下来加速后续回答；KV 缓存对齐指压缩时尽量不弄乱这张草稿纸，让速度不打折 |
| 上下文窗口（Context Window） | AI 一次能"记住"的最大对话量，超出就要靠压缩来腾地方 |
| 开源 | 源代码公开免费，任何人都能看、能改、能分享 |
| 许可证（License） | 规定"代码怎么用才合法"的法律条款，dsh 用的是 MIT 许可证（见第 12 章） |
| 开发者预览（Developer Preview） | 还没正式发布、仍在快速迭代的版本，功能可能随时变化 |
